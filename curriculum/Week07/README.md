## 📚 学習内容

### 1. スクリプトの基本構造

#### 💡 シバン行（`#!/bin/bash`）とは
スクリプトの1行目に書く `#!/bin/bash` を「シバン（shebang）」という。
`#!` はカーネルに対して「このファイルは `/bin/bash` で実行してください」と指示する特殊な記法。
これがないと `./script.sh` の形式で実行したとき、どのインタプリタを使うか分からず失敗することがある。

#### 💡 `set -euo pipefail` の意味
デフォルトのbashは「エラーが出ても次の行を実行し続ける」という挙動をする。
これは運用スクリプトでは危険（途中でエラーが出ても気づかずに処理が続く）。
以下の3つをセットで使うことで「エラーを見逃さない」スクリプトになる。

```bash
#!/bin/bash
set -e        # errexit: コマンドが0以外の終了コードを返したら即終了
set -u        # nounset: 未定義の変数を参照したらエラー（タイポ対策）
set -o pipefail # パイプの途中でエラーが起きてもキャッチする

# readonly で定数を定義（後から変更できなくなる）
readonly LOG_FILE="/var/log/myapp/backup.log"
readonly BACKUP_DIR="/backup"
readonly RETENTION_DAYS=7

# ログ出力関数（タイムスタンプ付き）
log() {
  echo "[$(date '+%Y-%m-%d %H:%M:%S')] $1" | tee -a "$LOG_FILE"
}

# trapでエラー時・終了時の処理を定義
# ERR: エラー発生時に実行
# EXIT: スクリプト終了時（正常・異常どちらでも）に実行
trap 'log "ERROR: 異常終了しました (line: $LINENO)"' ERR
trap 'rm -f "$LOCK_FILE"' EXIT
```

### 2. 引数処理とバリデーション

#### 💡 引数チェックの重要性
「引数が足りない」「パスが間違っている」ままスクリプトが動くと、
想定外のディレクトリを削除するといった事故につながる。
スクリプト冒頭で必ず入力値をチェックする習慣をつける。

```bash
# 位置引数（$1, $2, ...）
TARGET_DIR="$1"

# 引数がなかったらエラーメッセージを出して終了
if [ -z "$TARGET_DIR" ]; then
  echo "Usage: $0 <target_dir>" >&2   # >&2 でエラー出力に書く
  exit 1
fi

# ディレクトリが存在するか確認
if [ ! -d "$TARGET_DIR" ]; then
  echo "Error: ディレクトリが存在しません: $TARGET_DIR" >&2
  exit 1
fi
```

### 3. よく使うパターン集

```bash
# ===== ロックファイルによる二重起動防止 =====
# スクリプトを cron で定期実行しているとき、前回の実行がまだ終わっていないのに
# 次の実行が始まると競合が起きる。ロックファイルで防止する。
LOCK_FILE="/tmp/backup.lock"
if [ -f "$LOCK_FILE" ]; then
  log "ERROR: すでに実行中です（$LOCK_FILE が存在）"
  exit 1
fi
touch "$LOCK_FILE"
trap "rm -f $LOCK_FILE" EXIT   # 終了時に必ずロックを解放

# ===== コマンドの成否確認 =====
if systemctl is-active --quiet apache2; then
  log "Apache: 起動中"
else
  log "ALERT: Apache が停止しています"
fi

# ===== 終了コード（$?）の確認 =====
ping -c 1 192.168.1.1 > /dev/null 2>&1
if [ $? -eq 0 ]; then
  echo "疎通OK"
else
  echo "疎通NG"
fi

# ===== ファイル・ディレクトリの存在確認 =====
[ -f /etc/apache2/apache2.conf ] && echo "Apache設定あり"
[ -d /var/log/apache2 ] || mkdir -p /var/log/apache2  # なければ作る
```
