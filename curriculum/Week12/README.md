## 📚 Week12 で補完する知識

### logrotate（ログのローテーション）

#### 💡 logrotateとは
Apacheなどのログは放置すると無限に肥大化する（Week08のディスクフル障害の原因になりうる）。
`logrotate` は「ログを定期的に切り替えて古いものを圧縮・削除する」デーモン。
`/etc/logrotate.d/` に設定ファイルを置くだけで動く。

```bash
# Apache の logrotate 設定を確認
cat /etc/logrotate.d/apache2

# 設定例：/etc/logrotate.d/hanamall
/var/log/apache2/shop_access.log /var/log/apache2/admin_access.log {
    daily          # 毎日ローテーション
    rotate 14      # 14世代分保持
    compress       # 古いログをgzip圧縮
    missingok      # ファイルがなくてもエラーにしない
    notifempty     # 空のファイルはローテーションしない
    sharedscripts
    postrotate
        systemctl reload apache2 > /dev/null 2>&1 || true
    endscript
}

# 手動でローテーションをテスト
sudo logrotate --debug /etc/logrotate.d/hanamall
```

## 🏁 総合構築課題

以下をすべて満たすサーバー環境を構築する。各項目を自力でチェックできること。

### チェックリスト

```
【SSH設定】
[ ] 公開鍵認証のみ許可（PasswordAuthentication no）
[ ] rootログイン禁止（PermitRootLogin no）
[ ] ~/.ssh/config に登録済みで ssh myserver だけで繋がる

【ユーザー・権限管理】
[ ] 作業用ユーザーを作成してそのユーザーで作業する（rootで作業しない）
[ ] sudo権限を必要なコマンドのみに限定（visudoで設定）

【Webサービス】
[ ] Apache が起動しており HTTP 200 が返る（curl http://localhost で確認）
[ ] 設定の文法チェック済み（apache2ctl configtest で Syntax OK）
[ ] バーチャルホストで任意のドメインを設定済み

【ファイアウォール】
[ ] SSH（22）・HTTP（80）のみ開放
[ ] その他のポートは閉鎖（firewall-cmd --list-all で確認）

【バックアップ】
[ ] cronまたはsystemdタイマーで毎晩自動取得するよう設定
[ ] rsyncで別ディレクトリにバックアップされる

【監視】
[ ] CPU・メモリ・ディスク使用率を定期記録するスクリプトが動いている
[ ] Apacheが落ちていたらログに記録するスクリプトが動いている

【ログ管理】
[ ] logrotate でログが日次ローテーションされる設定

【ドキュメント】
[ ] 構築手順をREADME.mdにまとめている（自分が忘れても復元できるレベル）
```

→ `hands-on/12_final_checklist.sh` を実行して自動チェックできる

## 💡 「インフラエンジニアの仕事」を改めて整理する

12週間を通じて、インフラエンジニアが日常的にやっていることを一通り体験した。
現場では大きく3つの仕事がある：

**1. 構築（Build）**：サーバーをゼロから作る
→ Week01〜05・Week08・Week11 で習得

**2. 運用（Operate）**：毎日サーバーを安定稼働させる
→ Week06（自動化）・Week09（パッケージ管理）・Week10（監視）で習得

**3. 障害対応（Troubleshoot）**：何か起きたときに素早く直す
→ Week10（障害対応シミュレーション）・全Weekのトラブルシューティング演習で習得
