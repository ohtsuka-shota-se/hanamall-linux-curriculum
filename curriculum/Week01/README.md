## 📚 学習内容

### 1. 環境構築

#### 💡 環境の選択肢と使い分け

学習環境には主に4つの選択肢がある。それぞれ一長一短があるので自分の状況に合わせて選ぶこと。

| 環境 | 手軽さ | 本番との近さ | Week08以降のディスク演習 | 向いている人 |
|------|--------|------------|----------------------|------------|
| **WSL2** | ◎ 最も簡単 | △ Windowsと共存 | ✕ 難しい | とにかく早く始めたい |
| **VirtualBox** | ○ やや手間 | ◎ 完全独立 | ◎ そのまま使える | 本番に近い環境で学びたい |
| **Proxmox** | △ 専用PCが必要 | ◎ 完全独立 | ◎ そのまま使える | 本格的に自宅ラボを作りたい |
| **AWS EC2** | ○ アカウント要 | ◎ 本番そのもの | ◎ EBSで演習可 | クラウドも同時に学びたい |

---

**① WSL2（Windows限定）**

Windowsに組み込まれているLinux実行環境。手軽に始められる反面、
ネットワーク設定やディスク管理はWindowsと共有しているため制限がある。

```bash
# PowerShell で実行
wsl --install -d Ubuntu-22.04

# 起動後確認
cat /etc/os-release
```

> **WSL2の注意点：** Week08（LVM・パーティション演習）は WSL2 では再現しにくい。
> その週だけ VirtualBox か AWS EC2 に切り替えることを推奨。

---

**② VirtualBox（Windows / Mac 対応）**

PC上に完全に独立した仮想マシンを立てる。本番サーバーに最も近い環境で学べる。
Week08のディスク管理演習もそのまま対応できる。

1. [VirtualBox 公式](https://www.virtualbox.org/) からインストール
2. [Ubuntu 22.04 Server ISO](https://ubuntu.com/download/server) をダウンロード
3. VirtualBox で新規VM作成 → ISOを指定してインストール

> **VirtualBox の注意点：** RAM を 2GB 以上割り当てること。
> ネットワークアダプターは「ブリッジアダプター」にすると
> ホストPCと同じネットワークに繋がり実機に近い練習ができる。

---

**③ Proxmox（自宅ラボ向け・上級者向け）**

古いPCや余っているマシンに入れる、本格的な仮想化基盤。
複数のVMを同時に立てられるため「複数台構成」の練習もできる。

1. [Proxmox VE](https://www.proxmox.com/en/downloads) のISOを専用PCに焼く
2. Webブラウザから管理画面にアクセスしてVMを作成
3. Ubuntu 22.04 Server をVMとしてインストール

> **Proxmox の注意点：** 専用のPCが1台必要。
> ただし一度セットアップすれば最も本番に近い環境で学べる。
> インフラエンジニアとして本格的に学びたい人には非常におすすめ。

---

**④ AWS EC2（クラウド）**

Week11で詳しく扱うが、無料枠で今すぐ使うこともできる。
本番と完全に同じ環境で演習できるが、操作ミスで課金されるリスクに注意。

> **EC2 の注意点：** 必ず「無料利用枠の使用アラート」を設定してから使うこと。
> インスタンスの停止忘れで思わぬ請求が来ることがある。

---

**どれを選ぶか迷ったら：**
- Windows PC を持っている → まず **WSL2** で始めて、Week08から **VirtualBox** に切り替え
- Mac を使っている → **VirtualBox** 一択
- 古いPCが余っている → **Proxmox** が最もおすすめ
- クラウドも同時に学びたい → **AWS EC2**（Week11まで待ってもOK）

### 2. ディレクトリ構造の理解

#### 💡 なぜディレクトリが決まっているのか
Linuxは「どこに何を置くか」がOSレベルで標準化されている（FHS: Filesystem Hierarchy Standard）。
この標準のおかげで、初めて見るサーバーでも「設定ファイルは `/etc/` にある」「ログは `/var/log/` にある」と見当がつく。

| ディレクトリ | 役割 | 具体例 |
|------------|------|--------|
| `/etc` | 設定ファイル置き場 | `/etc/apache2/apache2.conf`, `/etc/hosts` |
| `/var/log` | ログファイル置き場 | `/var/log/syslog`, `/var/log/auth.log` |
| `/home` | ユーザーのホームディレクトリ | `/home/ubuntu/` |
| `/tmp` | 一時ファイル（再起動で消える） | スクリプトの一時出力など |
| `/usr/bin` | 一般コマンドの実体 | `ls`, `grep`, `curl` など |
| `/usr/local/bin` | 手動インストールしたコマンド置き場 | 自作スクリプト、独自ツール |
| `/opt` | サードパーティ製ソフトの置き場 | `/opt/myapp/`, `/opt/datadog-agent/` など |
| `/proc` | カーネルの状態（仮想FS） | `/proc/cpuinfo`, `/proc/meminfo` |

> **`/opt` の使われ方：** `apt` や `yum` で入れるパッケージは `/usr/` 以下に展開されるが、
> 公式サイトからダウンロードしたソフトや社内製アプリは `/opt/` に置くのが慣習。
> 例えば Datadog エージェントや Jenkins、自社開発の監視ツールなどが `/opt/` 配下に入ることが多い。

### 3. 基本コマンド

#### 💡 コマンドの読み方
Linuxコマンドは `コマンド名 [オプション] [引数]` の形式。
オプションは `-` から始まる短縮形（`-l`）と `--` から始まる長い形式（`--long`）がある。

```bash
# ファイル操作
ls -la          # -l: 詳細表示, -a: 隠しファイル(.で始まるもの)も表示
cd /var/log     # ディレクトリ移動（cd = change directory）
cp file1 file2  # コピー（cp = copy）
mv file1 dir/   # 移動・リネーム（mv = move）
rm -rf dir/     # 再帰削除（-r: ディレクトリごと, -f: 確認なし）
mkdir -p a/b/c  # -p: 途中のディレクトリも一括作成

# 検索
find /etc -name "*.conf"           # /etc以下で名前が*.confのファイルを探す
grep -r "error" /var/log/          # /var/log/以下のファイルを再帰的に検索
grep -n "keyword" file.txt         # -n: 行番号付きで表示

# ファイル確認
cat file.txt                       # ファイル全体を一気に表示
less /var/log/syslog               # ページ送りで表示（q で終了, /で検索）
tail -f /var/log/syslog            # -f: ファイルの末尾をリアルタイムで追跡
head -20 /var/log/auth.log         # 先頭20行だけ確認
```

#### 💡 `tail -f` が現場でよく使われる理由
サーバーのログは常にリアルタイムで追記される。`tail -f`（follow）は
ファイルへの新しい書き込みを自動で表示してくれるため、
「今サーバーで何が起きているか」をその場で確認する標準的な手段になっている。

### 4. パーミッション

#### 💡 なぜパーミッションが必要なのか
Linuxは複数のユーザーが同時に使うマルチユーザーOSとして設計されている。
「Aさんの設定ファイルをBさんが書き換えられる」「Webサーバーの設定をゲストユーザーが消せる」
といった事故を防ぐために、すべてのファイルに「誰が・何をできるか」の権限が設定されている。

```bash
# ls -la の出力を読む
# -rwxr-xr-- 1 ubuntu www-data 1234 May 1 10:00 script.sh
#  ↑①       ↑②  ↑③     ↑④    ↑⑤
#
# ①パーミッション ②リンク数 ③所有ユーザー ④所有グループ ⑤ファイルサイズ
#
# パーミッションの読み方：
# - : ファイル（d=ディレクトリ, l=シンボリックリンク）
# rwx : 所有ユーザー（ubuntu）の権限：読み・書き・実行できる
# r-x : 所有グループ（www-data）の権限：読み・実行はできるが書き込み不可
# r-- : その他全員の権限：読み込みのみ

chmod 755 script.sh   # rwxr-xr-x（スクリプトに実行権限を付ける定番）
chmod 644 file.txt    # rw-r--r--（設定ファイルの定番）
chmod 600 ~/.ssh/id_rsa  # rw-------（秘密鍵は自分だけ読める必要がある）
chown ubuntu:www-data file  # 所有者をubuntu、グループをwww-dataに変更
```

**よく使うパーミッション早見表：**

| 数値 | 意味 | 用途 |
|------|------|------|
| 755 | rwxr-xr-x | スクリプト・実行ファイル |
| 644 | rw-r--r-- | 設定ファイル・テキスト |
| 600 | rw------- | SSH秘密鍵（`~/.ssh/id_rsa`） |
| 700 | rwx------ | 秘密ディレクトリ（`~/.ssh/`） |

### 5. vim基礎

#### 💡 なぜvimを覚えるのか・viとの違いは？

**vi と vim の関係：**
- **vi**：1976年に登場した元祖テキストエディタ。Unix系OSに標準搭載されている。
- **vim**（Vi IMproved）：viを大幅に機能強化した後継版。「viの上位互換」と思えばOK。

実は多くのLinux環境では `vi` と打っても中身は `vim` が起動する（エイリアスになっている）。
ただし最小構成のサーバー（コンテナや組み込み系）では本当の `vi` しか入っていないこともある。
**「vimの操作を覚えておけばviでも困らない」** というのが現場の共通認識。

```bash
# どちらが起動するか確認する方法
vi --version 2>&1 | head -1
# "VIM - Vi IMproved" と出ればvimが動いている

# vimが入っていない環境での代替手段
nano /etc/hosts   # viより直感的（Ctrl+O で保存、Ctrl+X で終了）
```

サーバーにはGUIがないことが多く、ファイル編集はターミナル上のテキストエディタで行う。
vimはほぼすべてのLinux環境にデフォルトでインストールされており、
リモートサーバーへのSSH接続中でも確実に使えるため、インフラエンジニアの必携スキル。

```
# vimには「モード」という概念がある。最初は「ノーマルモード」で起動する。

ノーマルモード（コマンドを入力する状態）
  i         → 挿入モードに入る（文字が打てるようになる）
  Esc       → 挿入モードからノーマルモードに戻る
  :w        → 保存（writeの略）
  :q!       → 保存せず強制終了
  :wq       → 保存して終了
  /keyword  → 検索（n で次のマッチへ移動）
  dd        → 現在行を削除
  yy        → 現在行をコピー
  p         → ペースト
  u         → アンドゥ（Ctrl+Zに相当）
```

## 🛠️ ハンズオン演習

### 演習1：/etc/hosts を編集して名前解決を追加する

**名前解決とは？**
ブラウザで `google.com` と打つと、裏では「google.com って IP アドレスで言うとどこ？」という問い合わせが走る。
これを **名前解決** という。通常は DNS サーバーが答えを返すが、
`/etc/hosts` はそれより先に参照される「手書きの電話帳」のようなもの。

```
google.com → DNSサーバーに問い合わせ → 142.250.x.x に繋ぐ
myserver.local → /etc/hosts を確認   → 192.168.1.100 に繋ぐ（DNS不要）
```

インフラ現場では「本番ドメインを本番DNSに向けずに手元で動作確認したい」
といったときに `/etc/hosts` を書き換えてテストすることがよくある。

```bash
# /etc/hosts の現在の中身を確認
cat /etc/hosts
# 127.0.0.1  localhost  ← 「localhost」は「自分自身」という意味

# 新しい名前解決を追加
sudo vim /etc/hosts
# 以下を末尾に追記する
192.168.1.100  myserver.local

# 保存後、名前で繋がるか確認
ping myserver.local
# → 192.168.1.100 に ping が飛べばOK
```
