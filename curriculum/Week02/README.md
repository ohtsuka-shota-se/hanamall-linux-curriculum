### 1. パイプとリダイレクト

#### 💡 標準入出力とは
Linuxのコマンドはすべて「どこから読んで、どこに書くか」が定義されている。
- **標準入力（stdin）**：キーボードからの入力（ファイルディスクリプタ 0）
- **標準出力（stdout）**：コマンドの結果（ファイルディスクリプタ 1）
- **標準エラー出力（stderr）**：エラーメッセージ（ファイルディスクリプタ 2）

パイプ（`|`）は「前のコマンドのstdoutを、次のコマンドのstdinに繋ぐ」仕組み。
これにより、単機能なコマンドを組み合わせて複雑な処理が実現できる。

```bash
# パイプ：| で繋いで「前の出力を次の入力に」
cat access.log | grep "500" | wc -l  # 500エラーの件数を数える

# リダイレクト：出力をファイルに書く
ls /etc > result.txt          # > は上書き（ファイルが既にあれば消えて作り直し）
echo "追記内容" >> result.txt  # >> は追記（既存の内容を残したまま末尾に追加）

# エラー出力だけをファイルに書く
find / -name "*.conf" 2> errors.txt

# 標準出力とエラー出力を同じファイルに書く（ログ記録でよく使う）
./script.sh > output.log 2>&1

# エラーを捨てる（画面に表示させたくないとき）
find / -name "*.conf" 2>/dev/null
```

#### 💡 `2>/dev/null` の意味
`2>` は「標準エラー出力（fd=2）をリダイレクトする」という意味。
`/dev/null` はLinuxの「ゴミ箱」。書き込まれたデータはすべて消える。
`find` を実行すると権限のないディレクトリで大量のエラーが出るが、
`2>/dev/null` で捨てることで結果だけをきれいに表示できる。

### 2. テキスト処理コマンド

#### 💡 テキスト処理の考え方
Linuxでは「1つのコマンドに1つの仕事をさせ、パイプで繋ぐ」という設計思想がある（Unix哲学）。
grep・awk・sedはそれぞれ役割が決まっており、組み合わせることで強力な処理ができる。

```bash
# grep：キーワード抽出（global regular expression print）
# 「正規表現にマッチする行を表示する」が本来の意味
grep "ERROR" app.log              # ERROR を含む行を抽出
grep -v "INFO" app.log            # -v: 逆マッチ（INFOを含まない行）
grep -i "error" app.log           # -i: 大文字小文字を無視
grep -c "404" access.log          # -c: マッチした行数だけ表示（count）
grep -E "(403|404|500)" access.log # -E: 拡張正規表現（OR検索）

# awk：列ベースのデータ処理（空白区切りの表形式データに強い）
# $1 = 1列目, $2 = 2列目, $NF = 最終列
awk '{print $1}' access.log           # 1列目（IPアドレス）だけ抽出
awk '$9 == "500" {print $1, $7}' access.log  # 9列目が500の行のIP+URLを表示
awk '{sum += $10} END {print sum}' access.log # 10列目（バイト数）を合計

# sed：文字列の置換・削除（stream editor）
sed 's/ERROR/【エラー】/g' app.log    # s/検索/置換/g の形式（g=全行）
sed -n '10,20p' access.log           # -n: 10〜20行目だけ表示

# sort / uniq：頻度集計の黄金パターン
# ※ uniqは「隣接する」重複しか除去できないのでsortが必須
awk '{print $1}' access.log | sort | uniq -c | sort -rn
# IPアドレスを抽出 → アルファベット順ソート → 重複を数える → 件数の多い順
```

#### 💡 `sort | uniq -c | sort -rn` の分解
これは現場で毎日使う黄金パターン。意味を分解すると：
1. `sort` → 同じ値を隣接させる（uniqのために必要）
2. `uniq -c` → 連続する同じ値を1行にまとめて前に件数を付ける
3. `sort -rn` → 件数で降順ソート（`-r`=降順, `-n`=数値として比較）

### 3. bash基礎

#### 💡 シェルとbashの違い
- **シェル**：ユーザーとOSカーネルの間に立つインタプリタ。コマンドを受け取って実行する。
- **bash**（Bourne Again Shell）：最も広く使われるシェルの実装。スクリプトの書き方も提供している。
- 他にもzsh, fish, dashなどがあるが、サーバーではbashが標準。

```bash
# 変数（スペースを入れてはいけない！ NAME = "value" はエラー）
NAME="server01"
echo $NAME
echo "ホスト名: ${NAME}"       # 変数名を明示したいときは{}で囲む

# 条件分岐
if [ -f /etc/nginx/nginx.conf ]; then  # -f: ファイルが存在する
  echo "Nginxの設定ファイルがあります"
elif [ -d /etc/apache2 ]; then          # -d: ディレクトリが存在する
  echo "Apacheの設定ディレクトリがあります"
else
  echo "Webサーバーが見つかりません"
fi

# for ループ
for i in 1 2 3 4 5; do
  echo "カウント: $i"
done

# コマンドの結果を変数に入れる（コマンド置換）
HOSTNAME=$(hostname)
DATE=$(date +%Y%m%d)
echo "バックアップ先: backup_${HOSTNAME}_${DATE}.tar.gz"
```

### 4. ジョブ管理

#### 💡 フォアグラウンドとバックグラウンド
通常コマンドを実行すると「フォアグラウンド」で動き、終わるまで次のコマンドが入力できない。
`&` を付けることで「バックグラウンド」実行になり、他のコマンドと並行して動かせる。

```bash
sleep 60 &         # バックグラウンドで実行（& を付けるだけ）
jobs               # バックグラウンドで動いているジョブ一覧
fg %1              # ジョブ番号1をフォアグラウンドに戻す
Ctrl+C             # フォアグラウンドのジョブを強制終了
Ctrl+Z             # フォアグラウンドのジョブを一時停止してバックグラウンドへ

# nohup：ターミナルを閉じても動かし続ける
# SSHを切断してもスクリプトが止まらないようにしたいときに使う
nohup ./long_script.sh > output.log 2>&1 &
```
